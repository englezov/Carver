## P1 Remediation

Prior local hostile audit found that downstream rows were still generated by copying full downstream row dicts from active segment artifacts through policy rows. That was a P1 because the fast runner would have been a wrapper around legacy artifact rows rather than an executable local mechanical row generator.

Remediation:

- downstream policy rows now carry only policy labels, row hashes, and bounded status fields;
- policy rows no longer embed `transition_row`, `fill_row`, `market_fill_metadata_row`, `cost_row`, `pnl_row`, or `validation_row` dict payloads;
- downstream rows are reconstructed from generated order rows, locked declared input pack rows, and the combined TBBO registry;
- active legacy segment artifacts are used only as parity oracle, not as generated row source;
- focused regression added to reject reintroduction of full downstream row dict copying.

The assembler P1s around primitive authority were also closed:

- `FastGeneratedSegmentAssembly.validate()` calls `primitive_bundle.validate()`;
- primitive runtime/forecast/desired rows are checked against primitive bundle row-family hashes;
- primitive row payload hashes are recomputed after removing `row_hash`, so stale-row-hash payload mutation is rejected.

## Post-Facade Integration Hardening

After generated segment assembly was integrated into `src/carver/spine/s27_v2_replay/fast_test_runner.py`, a follow-up local hostile audit found one remaining P1:

- downstream policy/status behavior was still partly derived from active downstream artifact ledgers rather than purely from generated order rows plus locked declared pack/TBBO source rows.

Remediation:

- `_build_policy_rows()` in `src/carver/spine/s27_v2_replay/fast_downstream_generator.py` no longer reads `artifacts.segment_rows_by_ledger` or any downstream artifact ledger;
- downstream policy/status fields are derived from generated desired/limit/no-market/market order rows and hash-verified declared decision/fill/valuation/cost row families;
- active downstream artifact ledgers remain only in `_validate_downstream_parity()` as an oracle, not as generation inputs;
- regression `test_fast_downstream_policy_builder_does_not_read_downstream_artifact_ledgers` directly inspects `_build_policy_rows()`.

The same follow-up audit found one P2:

- combined TBBO registry bytes were hashed but not compared to `combined_market_order_tbbo_registry_manifest.json` before generation use.

Remediation:

- `_load_downstream_source()` now reads `combined_market_order_tbbo_registry_manifest.json`;
- it verifies `registry == combined_market_order_tbbo_registry.csv`;
- it verifies `registry_sha256` equals the current combined TBBO CSV byte SHA256 before reading TBBO rows;
- regression `test_fast_downstream_source_loader_rejects_forged_tbbo_manifest_hash` covers forged TBBO manifest-hash rejection.
